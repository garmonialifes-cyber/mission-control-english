# Как перенести тренажёр на себя

Инструкция для мамы Дениса. Ничего знать заранее не нужно,
терминал и командная строка не понадобятся нигде.
Всё делается в браузере и в одной программе, которая ставится в два клика.

Всего три части, каждую можно делать в свой день:
1. Регистрация на GitHub — 5 минут
2. Получить проект — 2 минуты, после того как вам его передадут
3. Научиться менять задания — 15 минут

---

## Часть 1. Регистрация на GitHub

GitHub — это склад для файлов приложения. Оттуда тренажёр и открывается
по ссылке. Регистрация бесплатная.

**Шаг 1.** Откройте в браузере **github.com**

**Шаг 2.** Нажмите кнопку **Sign up** в правом верхнем углу.
Если сайт на английском — так и должно быть, русского там нет.
Нужные кнопки названы ниже, их всего несколько.

**Шаг 3.** Заполните три поля:

| Поле | Что вписать |
|---|---|
| **Email** | ваша почта — на неё придёт код подтверждения |
| **Password** | придумайте пароль, минимум 8 знаков, с цифрой |
| **Username** | ваш ник на сайте — латиницей, без пробелов |

Про **Username**: это ваше имя в системе, его потом видно в адресе приложения.
Например `irina-denis` или `irinam2026`. Если пишет *Username is already taken* —
такой ник уже занят, добавьте цифры и попробуйте снова.
**Запишите этот ник** — он понадобится на третьем шаге.

**Шаг 4.** Сайт спросит, хотите ли получать письма с новостями —
можно ответить **n** или снять галочку. На работу это не влияет.

**Шаг 5.** Появится проверка «вы не робот» — несложная картинка-головоломка.

**Шаг 6.** Нажмите **Create account**.

**Шаг 7.** На вашу почту придёт письмо с **кодом из восьми цифр**.
Впишите его на сайте. Если письма нет — проверьте папку «Спам».

**Шаг 8.** Дальше сайт может спросить, для чего вы пришли,
сколько человек в команде и что вас интересует.
Это анкета, её можно пропустить — ищите **Skip** внизу страницы.
Если пропустить не получается, отвечайте что угодно, на работу это не влияет.

**Готово.** Вы зарегистрированы. Теперь **пришлите свой ник** тому,
кто передаёт вам проект.

---

## Часть 2. Получить проект

Вам придёт письмо с приглашением. Нужно его принять.

**Шаг 1.** В письме нажмите зелёную кнопку приглашения.
Если письмо потерялось — зайдите на github.com, вверху справа значок колокольчика,
приглашение будет там.

**Шаг 2.** На открывшейся странице нажмите **Accept**.

Теперь проект ваш. Адрес приложения станет таким:

```
https://ваш-ник.github.io/mission-control-english/
```

**Шаг 3.** Проверьте, что приложение открывается по новому адресу.
Если пишет 404 — подождите пару минут и обновите страницу,
GitHub собирает сайт не мгновенно.

**Шаг 4.** Если адрес не заработал за десять минут — включите его вручную:
в своём проекте вкладка **Settings** → слева в меню **Pages** →
в поле **Branch** выбрать **main** → **Save**.

Дайте Денису новую ссылку, старая перестанет работать.

## Часть 3. Менять задания самой

Это понадобится, когда захотите добавить заданий или что-то поправить.
Без этого приложение и так работает.

### Один раз: поставить программу

**Шаг 1.** Откройте **github.com/apps/desktop** и скачайте **GitHub Desktop**.
Это обычная программа, ставится как любая другая.

**Шаг 2.** Запустите её, войдите своим ником и паролем от GitHub.

**Шаг 3.** Внутри программы: **Clone a repository** →
в списке выберите **mission-control-english** → **Clone**.

Программа скачает папку с приложением к вам на компьютер
и запомнит, где она лежит.

### Каждый раз, когда хотите что-то изменить

**Шаг 1.** Откройте эту папку в **Codex**.
В Codex: **Open folder** → выбрать папку проекта.

**Шаг 2.** Первым сообщением напишите:

```
Прочитай AGENTS.md в этой папке — там описан проект,
формат заданий и правила разбора ошибок.
Расскажи своими словами, что понял.
```

Это важно: в папке лежит инструкция для Codex, где описано,
как устроены задания и каким должен быть разбор ошибки.
Если он её не прочитает, то начнёт делать по-своему.

**Шаг 3.** Дальше пишите задачу обычными словами. Например:

```
Добавь 10 заданий в отсек «Поступки героев».
Формат и правила — из AGENTS.md.
Сначала покажи текстом, в файл не пиши.
```

Последняя строчка полезная: сначала посмотрите глазами,
и только потом разрешайте записывать в файл.

**Шаг 4.** Проверьте, что получилось: откройте файл **index.html**
двойным кликом — приложение запустится у вас в браузере.

**Шаг 5.** Выложите изменения. В GitHub Desktop:
внизу слева напишите одной строчкой, что сделали
(например «добавила задания по чтению») → кнопка **Commit to main** →
потом вверху **Push origin**.

Через минуту по вашей ссылке уже новая версия.

---

## Два правила, которые лучше не нарушать

**В файлах с заданиями первый вариант ответа всегда правильный.**
На экране варианты перемешиваются сами. Если их переставить местами,
проверка ответов сломается.

**Codex склонен разгоняться.** Попросите добавить задания — он может
предложить поднять сервер, подключить базу данных и поставить сторонний
хостинг. Всё это здесь не нужно. Держите его в рамках одной задачи
и просите показывать план до того, как он начнёт править файлы.

---

## Если что-то пошло не так

**Приложение перестало открываться** — проверьте Settings → Pages,
в поле Branch должно стоять main.

**Сломали что-то в файлах** — на GitHub видна вся история правок,
можно вернуться к любой предыдущей версии. Ничего не теряется навсегда.

**Приложение показывает старое** — обновите страницу с нажатым Shift,
браузер держит старую версию в памяти.
